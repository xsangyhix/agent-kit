# 0002 — Agent workflow v2

- **Status**: superseded by ADR-0003–0006
- **Context**: ADR 0001 fixed the agent workflow as a seven-state machine over local markdown issues. The issue-002 session (2026-10-13/14, retrospective at `.scratch/workflow-refactor/retro-2026-10-14-issue-002-session.md`) exposed three defects. The machine never said *who* flips a unit's state, so the agent stalled waiting for permission to advance from `questioning` and the user had to correct it. Two of the seven states (`ready`, `changes-requested`) were never written to any file while the real path skipped them. The vocabulary collided: `Issue` meant both "any tracked file" and "an incoming report you didn't create", and neither `Spec` nor `Ticket` existed, so the skills' pipeline had to be translated on every use. Separately, nothing prevented an agent from committing on `dev`; one did, and the branch had to be repaired by hand.
- **Decision**: Adopt the canonical tracked-unit vocabulary, a reworked state machine, and guardrails behind both.
  - **Vocabulary.** `Issue` is the supertype for any tracked file. Its roles are `Raw issue` (user-created, the only input `/triage` accepts), `Spec` (feature-level, optional — earned by size), and `Ticket` (the unit of work). `Idea` is pre-tracking; `Retro` is findings and is not tracked. `task` and `artifact` are not terms.
  - **Layout.** Tracked units live at `.scratch/<feature>/issues/<NN>-<slug>.md`, numbered from `01` in dependency order; closed units move to `.scratch/<feature>/issues/closed/`.
  - **Header.** `Labels:` then `Status:`, with no H1 (the filename carries the number and the slug). `Labels` is optional while the unit is active, is removed at close, and is an axis independent of status.
  - **State machine.** Eight states, every transition owned by exactly one actor: `draft` (user) → `awaiting-agent` (agent) → `questioning` (user) / `in-progress` (agent) → `in-review` (user) → `done`; `review-feedback` (agent) is review's negative edge and `blocked` (either) holds work whose handling is undecided. `ready` and `changes-requested` are retired. The agent picks up `awaiting-agent`; `blocked` is not pickable.
  - **Creation and close.** The user creates raw issues; the agent creates tickets, defaulting to `awaiting-agent`. `draft` is the user's hold state, or the agent's only on explicit request. The user setting `Status: done` *is* the approval; the agent then performs the close.
  - **Guardrails.** Versioned pre-commit hooks refuse a `dev` commit made in an Agent session, refuse if the tracker path is gitignored, and validate the tracker's file invariants. *How* each check is implemented is owned by `docs/agents/workflow.md`.
  - **Deviations.** Where these diverge from `/to-tickets`' local-tracker defaults, `docs/agents/issue-tracker.md` records every override in one place.
- **Consequences**: Supersedes ADR 0001, which remains as the historical record. `GLOSSARY.md`, `docs/agents/workflow.md` (now `Version: 2`), `docs/agents/triage-labels.md` and `docs/agents/issue-tracker.md` are rewritten to match. The triage label scheme survives, as a planning axis over the workflow states. Review stays lightweight (comments in the issue file) and the agent still cannot merge or push. A future change to the state machine or to the vocabulary needs a new ADR; routine wording inside `workflow.md` does not.
